# Explore With Me

Временная инструкция по локальному запуску проекта. Полноценный README будет подготовлен после интеграции командных
модулей.

## Требования

- Java 21
- Maven
- Docker и Docker Compose

## Запуск

Из корневого каталога проекта собрать Maven-модули:

```bash
mvn clean package -DskipTests
```

Собрать Docker-образы и запустить контейнеры:

```bash
docker compose up -d --build
```

Проверить состояние контейнеров:

```bash
docker compose ps
```

## Доступные сервисы

| Сервис                       | Адрес                 |
|------------------------------|-----------------------|

Проверить доступность приложений:

```bash
curl http://localhost:8080/actuator/health
curl http://localhost:9090/actuator/health
```

Ожидаемый ответ:

```json
{
  "status": "UP"
}
```

Проверить публичный API мероприятий:

```bash

```

## Остановка

```bash
docker compose down
```

Команда останавливает и удаляет контейнеры проекта без явного удаления томов с данными.

## API мероприятий

Основной сервис (`ewm-main-service`) реализует создание, редактирование, модерацию и публичный поиск мероприятий.

Базовый адрес API: `http://localhost:8080`.

### Эндпоинты

**Личный API организатора**

| Метод | Эндпоинт                           | Описание                                 |
|-------|------------------------------------|------------------------------------------|
| POST  | `/users/{userId}/events`           | Создание мероприятия                     |
| GET   | `/users/{userId}/events`           | Получение мероприятий пользователя       |
| GET   | `/users/{userId}/events/{eventId}` | Получение мероприятия пользователя по ID |
| PATCH | `/users/{userId}/events/{eventId}` | Редактирование мероприятия               |

**Административный API**

| Метод | Эндпоинт                  | Описание                                              |
|-------|---------------------------|-------------------------------------------------------|
| GET   | `/admin/events`           | Поиск мероприятий с фильтрацией                       |
| PATCH | `/admin/events/{eventId}` | Редактирование, публикация или отклонение мероприятия |

**Публичный API**

| Метод | Эндпоинт            | Описание                                    |
|-------|---------------------|---------------------------------------------|
| GET   | `/events`           | Поиск опубликованных мероприятий            |
| GET   | `/events/{eventId}` | Получение опубликованного мероприятия по ID |

### Жизненный цикл мероприятия

При создании мероприятие получает статус `PENDING` и ожидает модерации.

- `PENDING` — ожидает рассмотрения администратором.
- `PUBLISHED` — опубликовано и доступно в публичном API.
- `CANCELED` — отменено или отклонено.

Администратор может опубликовать мероприятие в статусе `PENDING` или отклонить мероприятие, которое ещё не опубликовано.

Организатор может редактировать мероприятия в статусах `PENDING` и `CANCELED`, отправлять их на повторное рассмотрение
или отменять рассмотрение.

При создании мероприятия дата начала должна быть не раньше чем через два часа. При публикации — не раньше чем через один
час.

### Публичный поиск

`GET /events` поддерживает следующие параметры:

| Параметр                 | Назначение                                       |
|--------------------------|--------------------------------------------------|
| `text`                   | Поиск по аннотации и описанию без учёта регистра |
| `categories`             | Фильтрация по категориям                         |
| `paid`                   | Платное или бесплатное мероприятие               |
| `rangeStart`, `rangeEnd` | Интервал дат проведения                          |
| `onlyAvailable`          | Только мероприятия со свободными местами         |
| `sort`                   | `EVENT_DATE` или `VIEWS`                         |
| `from`, `size`           | Пагинация                                        |

Если границы диапазона дат не указаны, возвращаются только будущие мероприятия.

Пример:

```bash
curl -G "http://localhost:8080/events" \
  --data-urlencode "sort=EVENT_DATE" \
  --data-urlencode "from=0" \
  --data-urlencode "size=10"
```

### Интеграция со статистикой

Основной сервис взаимодействует с сервисом статистики через HTTP-клиент.

- При обращении к публичным эндпоинтам `/events` и `/events/{eventId}` регистрируются просмотры.
- Количество просмотров включается в DTO мероприятий через поле `views`.
- Для получения статистики используется сервис `stats-server` (порт `9090`).
- Статистика просмотров мероприятий запрашивается с учётом уникальных IP-адресов.

### Интеграция с другими модулями

**Пользователи и категории**

При создании мероприятия проверяется существование организатора и категории. Соответствующие сущности используются в
модели мероприятия.

**Заявки на участие**

Интеграция с модулем заявок пока не завершена:

- `confirmedRequests` временно возвращает `0`.
- `onlyAvailable=true` пока не реализован и возвращает `501 Not Implemented`.
- После подключения модуля заявок потребуется получать количество подтверждённых заявок и учитывать ограничение
  `participantLimit`.

### Обработка ошибок

API использует единый формат `ApiError`, соответствующий спецификации проекта.

Основные HTTP-статусы:

- `400 Bad Request` — некорректные параметры или ошибки валидации.
- `404 Not Found` — запрошенная сущность не найдена.
- `409 Conflict` — нарушение бизнес-правил, например попытка опубликовать мероприятие в неподходящем статусе.
- `501 Not Implemented` — временно не реализованная проверка доступности мест.

### Проверка

Получение опубликованных мероприятий:

```bash
curl http://localhost:8080/events
```

Получение статистики публичного API:

```bash
curl -G "http://localhost:9090/stats" \
  --data-urlencode "start=2026-11-25 00:00:00" \
  --data-urlencode "end=2026-11-26 00:00:00" \
  --data-urlencode "uris=/events" \
  --data-urlencode "unique=false"
```

Даты в запросе статистики необходимо выбирать в соответствии с периодом тестирования.
